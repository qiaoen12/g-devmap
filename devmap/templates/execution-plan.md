# Canonical Execution Plan

这是 `## Execution` 区块内部的静态专业规划数据，使用 Markdown 即可，不要求运行程序或序列化工具。它不是整个任务来源的模板。任务来源在这个标题之前可以是任意背景，不要求固定标题或字段；没有 `## Background` 也可以。

字段名固定，值按项目填写；未知写明缺口，无内容写“无”，不要制造事实。L0～L3 仅是地图显示层的名称。

## Plan Identity / Scope

- Plan ID / revision：稳定标识及修订号；局部修订保留前版引用 / 差异说明。
- Title：用户地图的任务名称。
- Source：任务素材的可访问引用或完整必要摘录。摘录保持素材原有写法，不要求来源先拆成固定前置字段。接管者能据此核对计划没有扩大原任务。
- Planned dependencies：预计新增软件依赖及理由，无则空集合；无法确定写未知（不与 Task 依赖混用）。

## Plan Basis

- Base branch / planning HEAD：规划所依据分支与完整提交标识。
- Relevant facts：真正影响方案的组件、ownership、结构事实；注明相关路径、事实和来源。
- Required entrypoints：会复用的工具 / 验证入口及用途；用于后续轻量检查。

只记录影响实施的现场依据，不保存命令输出、大段代码或普通日志。预期新建文件列在 Task 的新增动作中，无需已经存在。

## Approach

已选择的实现方式、重要取舍及理由，解释为何按这些 Task 实施。内容足够让另一 Agent 延续方案，不列未采纳的无关备选方案。

## Tasks

有序集合；ID 唯一且重开不变；顺序作为同优先级显示 / 下一步的稳定顺序。每项包含：

- ID / Name：稳定标识与简短中文名称。
- Purpose：目的及对应来源验收引用。
- Changes：具体要改什么、采用何种方式。
- Expected files：仓库相对路径与新增 / 修改 / 删除动作；去重集合，无法确定写未知。重命名保留旧、新路径；避免仅用目录或 glob 冒充已枚举文件数。
- Verification：本 Task 要求验证的 ID 集合；定义见下方，复用同一检查时引用同一 ID。
- Depends on：必要前置 Task ID 集合，无则空集合。依赖必须指向本计划存在的 ID 且无环；格式 / 引用错误先修正，不靠猜测生成可执行顺序。

不同时维护“预期结果 + 完成条件”两份重复字段；目的表达价值，Changes 表达实施，Verification 中的通过条件承担完成核对。

## Global Verification

统一定义 Task 与整体交付需要的验证；Task 引用同一处定义，避免重复计数。每项记录：

- ID：稳定且唯一。
- Stage：Local / Integration / CI / Final，按实际验证用途组织，不以 L0～L3 为原始模型。
- Kind：规范检查 / 单项验证 / 联合验证 / 最终验收；用于稳定地图映射，同一 Stage 可包含不同 Kind。
- Scope：Task ID 集合或全局；全局 Final 条件用于最终门槛，不要求无关 Task 等待它才完成。
- Requirement / entrypoint：验证内容、可复用入口或人工检查步骤。
- Pass criterion：可观察的通过条件；不得扩大来源验收。
- Count：单位与可枚举检查项 ID；同一等级使用相同单位，不能将 CI job 数冒充测试用例数。不可枚举写未知；明确不适用的类别列明理由。

这是计划要求，不存 passed、failed、当前版本结果或时间戳。执行结果归 Runtime。所有要求的 Final 项通过才可报告最终成功；最终验收缺失时核对来源，不能凭空宣布通过。

## Risks / Stop Conditions

仅记录使实施前提失效、需要重规划或负责人决定的风险：条件、影响的 Task、需要核对 / 决定的事项。没有则写无。普通测试失败与原范围内 bug 修复继续按 Runtime 处理。

## Reuse / revision note

初次规划写“初次规划”；复用无需改变原计划。发生事实漂移才记录证据、受影响字段与本次修订理由，保留前版预计范围用于比较。此处不记录开发状态、实际文件、测试结果、blocker 或报告历史。识别或复用本区块不会把它或地图写入远端；也不赋予写任务来源、开发或 merge 的权限。
