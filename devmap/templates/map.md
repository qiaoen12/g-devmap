# 地图模板

按事件只选择以下一种结构并替换占位项。用户可见层使用简洁中文；默认不复述 Issue / PRD，不展开命令、日志、预期结果、完成条件或依赖。Task 名称是看板格子的默认内容。所有地图使用相同的 L0～L3 测试表。路径摘要优先使用目录树；真实文件数单独保留，折叠不得丢失或重复计数。

## Execution Plan → Runtime → 地图字段映射

读取 [canonical Plan](execution-plan.md) 后只投影，不在渲染时重拆 Task、改范围或补验证。以下为内部映射，不展示给负责人。

| 地图字段 | 数据来源与规则 |
|---|---|
| 任务名称 | Plan Title |
| 总任务 / 已完成 / 当前阻塞 | Tasks 数量 / Runtime 已完成 Task 数 / 带当前 blocker 的 Task 去重数 |
| 四列看板 | 按 Tasks 原顺序，一 Task 一行；Name 放入 Runtime 状态列，blocker 附简短标记 |
| 预计文件与路径树 | 所有 Expected files 路径并集；按路径排序生成目录树，同路径不因不同 Task 重算；任一集合未知则总数未知，仍可展示已知路径 |
| 预计改动 / 新增依赖 | Expected files 动作及路径 / Planned dependencies 去重数量，未知保持未知 |
| 实际文件、增删、范围变化 | Runtime 实际集合与保留的计划对比；数量相等不代表范围一致 |
| 测试表 | 验证 ID 与检查项 ID 去重，再接 Runtime 当前适用结果；Kind 规范 / 单项 / 联合 / 最终分别映射 L0 / L1 / L2 / L3，Stage CI 不直接等同某个等级 |
| 当前问题 | Runtime 当前 blocker 的简短原因，按 Task 顺序；无则“无”，未经核实则未知 |
| 下一步 | 已在开发 / 测试且未阻塞的 Task 优先；否则取依赖均已完成、未阻塞的待开始 Task；同级按计划顺序。无可执行 Task 时显示已知等待原因；Task 全完成则核对未完成的 Final 要求 |

Task 地图仅筛选该 Task 的文件和验证（重开可含推翻其完成结论的全局项）；最终地图对全部文件、检查项去重。没有运行证据的已知计划验证记待做，不适用须有明确依据。不能映射 / 混合单位时对应行写未知并说明，不临时发明新验证。上述“下一步”只生成提示，不执行或编排开发。

四列 Task 看板排版规则：

- 一个 Task = 一行；每行只在该 Task 所属状态列填写名称，同一状态的多个 Task 纵向排列。
- 禁止使用 `<br>`、字面量 `\n` 或其他 HTML 换行，把多个 Task 塞进同一个单元格。
- 没有任何 Task 的空列只在首行显示“—”，后续行保持空白；有 Task 的列在其他 Task 所占行中保持空白。
- Task 名称过长时允许渲染器自然换行，不得手工插入 HTML。

## 文件树与计数规则

- 计划或实际文件不超过 30 个时，尽量展开真实路径并按目录组织成树。
- 超过 30 个文件时，按不重叠目录折叠并显示每个目录包含的真实文件数；仍超过约 30 行时继续向父目录折叠。
- 重要文件可以单独显示，但须从目录计数中扣除，并写明“其余”文件数。
- 表头中的计划 / 实际真实文件数不等于目录树的展示项数。每个文件只能由一个树叶或目录项代表；目录项不得重叠，展示数须守恒。
