# DevMap v1.3 LLM 场景验收

本文只保留需要模型判断的 8 个场景。文件计数、集合比较与目录折叠由 `tests/test_devmap_facts.py` 覆盖，不在此重复。所有输入均为固定 Mock，不是本仓库的开发记录。

重放方法：在全新会话中先读 `devmap/SKILL.md` 与 `devmap/templates/map.md`，把各场景“输入”交给模型并调用 /devmap，按“判据”验收。场景中给出的 facts 输出视为脚本已在 Mock 仓库运行的结果，模型不得改写其中的数字。

公共 Mock：需求“账单功能”——用户能查看账单、下载 CSV，帮助页说明这两项功能；下载依赖账单数据。可读文件：`src/bills.ts`、`src/export.ts`、`docs/help.md`。

## 1. 无 `## Execution`：生成最小基准并出开工快照

输入：上述需求原文，没有 `## Execution`，尚未开发。facts：`--planned src/bills.ts src/export.ts docs/help.md` 后计划 3、实际 0。

判据：
- 自行生成 Task 名称、预计文件、验证项三样，不写方案、依赖或完整计划，不要求用户补结构或拆 Task。
- 输出一张快照：所有 Task 为待开始；计划 3 / 实际 0；验证项为待做；不出现“需要你处理”。
- 不写主观百分比。

## 2. 有 `## Execution`：照原样读取，不重新规划

输入：来源前半是任意聊天素材，随后是 `## Execution`，列出 3 个 Task：查看账单（`src/bills.ts`，验证：账单显示检查）、下载账单（`src/export.ts`，验证：导出检查、下载联合检查）、更新帮助（`docs/help.md`，验证：文案检查）。另附一句 Agent 偏好“把下载拆成两个 Task”。尚未开发。

判据：
- 照原样使用 3 个 Task 的名称、顺序、文件和 4 个验证项；不拆分、不新增验证或 E2E。
- 不因为缺少 `## Background` 或前文结构随意而重新规划。
- 同一来源若标题写成 `## Execution Plan`，按“没有 `## Execution`”处理（回到场景 1 的行为）。

## 3. 进行中快照，含计划外文件

输入：场景 2 的计划。查看账单已完成且验证通过；下载账单开发中。facts：计划 3，实际 3（修改 `src/bills.ts`、修改 `src/export.ts`、新增 `src/csv-util.ts`）；计划外 `src/csv-util.ts`；尚未改动 `docs/help.md`。

判据：
- 状态：查看账单已完成、下载账单开发中、更新帮助待开始。
- 改动数字、计划外与尚未改动集合和目录树直接取 facts，不手工重数。
- 计划外文件如实列出并给一句原因或“原因未知”，不当作问题上报给负责人，也不改写原计划。

## 4. 有阻塞：显示“需要你处理”

输入：场景 3 之后，下载账单进入测试中；联合检查需要外部下载服务权限，已核实当前授权无法取得。更新帮助开发中，与下载无关。

判据：
- 下载账单显示“测试中 · 阻塞”，不新增第五状态。
- “需要你处理”写明原因、需要的决定或外部条件、影响，以及更新帮助可继续。
- 普通测试失败（例如一次可自行修复的文案检查失败）不得写成阻塞。

## 5. 全部完成

输入：3 个 Task 均已完成，4 个验证项全部通过；最终验收（人工查看账单、下载 CSV、阅读帮助）全部通过；无阻塞。facts：计划 3 / 实际 3，无计划外。`--pr` 结果：通过 1、失败 0、进行中 0。

判据：
- 结论为可交付 / 已完成；不显示“需要你处理”。
- 自动检查写“通过 1”，不展开版本标识或命令。

## 6. 最终验收未通过：不能显示“完成”

输入：同场景 5，但最终验收中“下载 CSV”发现缺少部分记录。

判据：
- 结论不得写“完成”或“可交付”；说明最终验收未通过。
- 下载账单回到开发中或测试中（不再是已完成），其余 Task 保持已完成。
- 若另一种变体是最终验收尚未运行，同样不得写“完成”，并写明待做。

## 7. 证据不足：写“未知”，不写 0

输入：在另一个窗口只给出 PR 号，本机没有该分支的副本；gh 不可用。只知道 Task 列表来自 PR 描述中的 `## Execution`。

判据：
- 实际文件数、计划外集合、自动检查写“未知”并说明原因（无本地副本 / gh 不可用），不写 0。
- Task 状态无法核实时写“未知”，不推测为待开始或已完成。
- 不写主观百分比，不编造数字。

## 8. 边界：只在改变结果时反问，不写远端，保存须给路径

输入 A：需求未说明“下载包含当前用户还是全公司账单”，这决定权限与产品行为。
输入 B：需求未指定 Task 名称和验证文件命名。
输入 C：用户调用 /devmap 后说“保存一下”，未给路径；随后给出路径 `notes/devmap.md`。

判据：
- A 只问一个会改变结果的问题；B 不反问，自行命名。
- 任何情况下都不写 Issue / PR 评论、不改写任务来源、不写远端。
- C 第一次询问保存路径，不自行选择；拿到路径后只保存到该路径。
