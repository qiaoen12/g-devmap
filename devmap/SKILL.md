# DevMap v1.3

仅在用户调用 /devmap 时启用，没有子命令。每次调用都按当前事实输出一张快照，不按事件推送，不回复“暂无新的地图事件”。DevMap 面向负责人，只观察和整理，不开发、不编排 Agent、不改变授权。

## 1. 输入

输入可以是 Issue 号、PR 号、分支、一段文本，或当前会话；可在开发会话中调用，也可在另一个窗口单独运行。只读：不写 Issue / PR 评论，不改写任务来源，不写任何远端。用户要求保存时，只写到用户指定的路径；未给路径就询问，不自行选择位置。

## 2. 计划基准

在来源中只找精确二级标题 `## Execution`（`## Execution Plan` 等不算）。

- **有**：照原样读取该区块，只取三样：Task 名称、预计文件、验证项。不重新拆 Task、不改范围、不补验证。
- **没有**：根据来源和仓库现状自行生成这三样，作为最小基准；不写完整方案，不要求用户补结构。

计划不扩大来源给出的范围；额外想法只作建议。只在缺失信息会改变结果（如产品行为、权限、范围）时反问，普通命名和拆分自行决定。

## 3. 确定性事实

以本文件所在目录为 `<skill>`，在目标仓库（或该分支的 worktree）根目录运行：

```
python3 <skill>/scripts/devmap_facts.py [--base REF] [--pr N] [--planned PATH ...]
```

- `--planned`：所有 Task 预计文件的并集；共享路径只算一次。
- `--base` 省略时取 `git merge-base origin/main HEAD`（没有 origin/main 则用 main；都不可用则报错）。实际改动口径 = `git diff -M --name-status <base>` + `git ls-files --others --exclude-standard`，含已提交、未提交与未跟踪文件。未暂存的 `mv` 显示为“删除 + 新增”。
- `--pr`：附自动检查计数；gh 不可用时为“未知”并给出原因。

输出 JSON：`counts`（新增 / 修改 / 删除 / 重命名 / 总数）、`sets`（计划、实际、计划外、尚未改动）、`trees`（≤30 行折叠目录树，展示计数之和等于真实总数）、`checks`。文件数、集合与目录树直接使用脚本结果，不手工重数。脚本报错（退出码非 0）时不猜测：相关数字写“未知”并说明原因。没有目标分支的本地副本时同样写“未知”。例外：来源有 `## Execution` 时，计划数取其预计文件并集（共享路径只算一次），即使脚本不可用也不写未知；实际数等其他数字仍按证据。

## 4. Task 状态

每个 Task 为 **待开始 / 开发中 / 测试中 / 已完成** 之一；阻塞是附加标记（如“测试中 · 阻塞”），不是第五状态。

- 实现完成且该 Task 所有验证项都通过才是已完成；未运行、失败、不可访问或结果未知都不算通过。
- 普通失败可继续修复，不算阻塞。只有缺少必需的批准、权限、负责人决定或外部依赖，在现有授权内无法继续时才标阻塞。
- 已完成的 Task 被后续验证推翻时回到开发中或测试中。
- 最终验收未通过、未运行或未知时，整体结论不能写“完成”。
- 证据不足以判断状态、数量或结果时写“未知”并说明原因；“未知”是正式状态，不用 0 代替，也不推测进度。

## 5. 输出

按 [map.md](templates/map.md) 输出一张快照，全部中文，面向负责人。数字来自脚本或可核实的证据，不给主观百分比，不展开命令、日志、完整计划或 Issue 长文。只在当前对话输出。
